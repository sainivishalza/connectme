3. Core Concepts
 
3.1 Dual-Mode Identity System (Key Innovation)
Mode Visibility Use Case Default?
Open Mode Full profile: photos, name, bio, age, location (relative only) Traditional dating, serious relationships Yes
Incognito Mode No photos, no name. Only: tags, one-line intro, mood, relative distance Hotel discovery, casual meetups, privacy-first users Toggle

 
Rules:
* Users choose mode per session or per match.
* Incognito Mode photos only unlock after mutual consent (both tap "Reveal").
* In Hotel Mode, Incognito is forced ON by default. Users can opt into Open.
* Mode cannot be changed mid-chat without both parties' consent. 
3.2 Hotel / Same-Place Discovery (Your Idea)
* User checks into a geofenced location (hotel, resort, conference, festival, airport lounge).
* App shows a private feed of other checked-in users.
* Identity hidden until mutual reveal.
* Icebreakers: send a virtual drink to another guest's room, "Anyone want dinner?" board.
* Auto-delete: All chats, photos, profile data tied to that location deleted 24 hours after checkout. 
3.3 Group Dates (Your Idea)
* Double Dates: 2 friends match with 2 friends. AI suggests venue, time, icebreakers.
* Group Dates: 2–6 people, activity-based (dinner, hiking, concert, bar crawl).
* AI Wingman joins group chat to suggest topics, venues, and logistics.

6. Technical Architecture
 
Frontend: Flutter (Dart) — one codebase for iOS + Android. Impeller renderer delivers 58–60 FPS on swipe UIs, 25% faster cold start than React Native.
 
Backend:
* Go (Golang) — core API, matching engine, geo-discovery. 180ms startup, 68MB under load.
* Node.js — real-time chat via Socket.io. Best WebSocket throughput.
* Python FastAPI — AI service (matching, moderation, wingman). 
Databases:
* PostgreSQL — users, profiles, matches, payments
* Redis — sessions, pub/sub, rate limiting
* MongoDB — chat messages
* Elasticsearch — geo-sharded nearby search 
Real-Time: WebSocket (Socket.io) + WebRTC (LiveKit) for calls.
 
Infrastructure: Docker + Kubernetes, AWS/GCP, CDN, Kafka for async. 
 
7. Security & Compliance Requirements
 
Non-negotiable:
* OWASP API Security Top 10 compliance
* bcrypt password hashing with auto-generated salt
* JWT with short expiry + refresh token rotation
* E2E encryption (Signal Protocol) for chats
* RBAC for users, moderators, admins
* Photo ID + liveness verification (prevent deepfake/catfish)
* CSAM hash matching before any media publish
* Location privacy: only relative distance, never exact coordinates
* Rate limiting per endpoint
* Auto-delete 24h after hotel checkout
* GDPR/CCPA erasure within 30 days
* 18+ age gate (no youth mode) 
Legal considerations:
* Hotel Mode must comply with local privacy laws (GDPR, CCPA, PIPL in China)
* Consent required before any identity reveal
* No exact room numbers shared ever
* Moderation team for 24/7 content review
